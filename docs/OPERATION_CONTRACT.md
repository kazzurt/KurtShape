# Shared operation contract

The authoritative document is native FreeCAD FCStd. A feature object's `Name` is its stable ID; native Sketcher constraints are parameters and native expressions are dependencies. `KurtShapeProject` stores project UUID, opaque revision, build status and source mapping, without duplicating editable geometry or dimensions. Studio operations additionally persist an ordered native feature list and logical part identities. Body resolution uses explicit `body`, the target/support's owning Body, or the sole current part. Several eligible parts without a target or explicit ID reject with `ambiguous_body`; assistants never inherit GUI focus. Historical and auxiliary Bodies are native dependencies and are excluded from current results.

`Controller.dispatch(request)` returns `{ok:true,result}` or `{ok:false,error:{code,message,...}}`. Successful document operations return inspection including `document_id`, `revision`, native features, `build_status`, measurements and `active_sketch_edit`. Mutations run serially on the GUI thread; the interface does not transport arbitrary executable code.

Create/open requests are `{op:"new",name:"Plate"}`, `{op:"open",path:"absolute.FCStd"}` and `{op:"import_step",path:"absolute.step"}` (also `.stp`, case insensitive). These create/select documents without an existing document/revision. Existing-document operations require `document_id`; every mutation, including undo/redo, sketch lifecycle, rebuild, save and export, also requires current `expected_revision`. Inspect requires no revision. Tokens are UUIDs rather than counters. Native modeling edits, undo/redo and reopen invalidate older tokens; stale requests reject before mutation.

## Contract 3.0 — Q03 lightweight status and explicit checks

Q03 publishes `contract:3` and `contract_revision:0`. Local validation passed 187 native, seven bridge and 22 shortcut cases plus 415 workflow checks; the full GUI sweep retained seventeen passes and its recorded carrier-history exception, and the status recipe passed seventeen checks. Paired five-repeat benchmarks and independent plate confirmation are recorded in the [Q03 record](architecture-responsiveness-upgrade/STATUS_REPORT.md#validation-and-source-versions), including open absolute targets. Revision, replay, ownership, write-root and native transaction guards retain their earlier semantics. The historical contract-2 records below describe their own increments.

Every request accepts optional `measure`, exactly JSON `false`, `true` or the string `"full"`. Omission defaults to `true`; explicit null, numeric 0/1 and other strings reject with `invalid_argument`. The field participates in canonical replay identity, including omission versus an explicit value. Direct Python `Controller.inspect(doc, measure=None)` uses the controller default; wire null is not that shortcut.

| Level | Measurements on a current solid result |
|---|---|
| `false` | `solid_count`; `volume_mm3`, `area_mm2`, `bbox_mm` and `center_of_mass_mm` are null |
| `true` | Solid count, volume, area and bbox; centre of mass is null |
| `"full"` | Solid count, volume, area, bbox and volume-weighted centre of mass |

`measurements.valid` is independently null until an explicit or export geometry check is cached, then reflects that verdict at any level. Aggregate and per-result `geometry_check` are `not_checked`, `valid`, `invalid` or `not_applicable` when there is no solid. Failed or unrecomputed intent has `measurements:null` and separately labeled `retained_geometry_measurements` at the requested level. `build_status:"valid"` means the native build/status checks succeeded; it does not imply BRepCheck ran.

`check_geometry` is read-only and requires `document_id`, with optional `body` identifying a current result or logical part. It checks selected/all current solids, returns inspection plus `geometry_check_report:{status,revision,engine,bodies,ms}`, and reports each body's `id`, `valid`, `issues` and `check_ms`. No solid rejects with `no_solid`. It reuses a source-shape verdict without changing revision, geometry or native history. Export first requires a current build, then performs/reuses valid geometry checks before staging output/provenance; an invalid verdict rejects with `invalid_geometry`.

The GUI sends `measure:false` on ordinary inspection/dispatch and displays solid count. **Check geometry** runs explicitly with a wait cursor and per-part Messages; **[ / Measure** measures selected geometry or requests full active-part mass properties without replacing the lightweight panel state. Measurement requests alone never run BRepCheck.

Transient geometry facts use the native object's own version, source Shape hash and source/occurrence placement dependencies. Shape-only versions key validity, so rigid placement changes invalidate world measurements without checking unchanged source topology. Each controller retains at most 1024 check verdicts and 4096 scalar/pair memo entries; eviction recomputes the same native result, and document close removes its data. Exact U2 common-volume/distance work follows conservative bbox rejection and caches exact parameters/frames/subelements; closest selectors retain all ties. Ordinary status reads cached health and cheap native-input/pending-scope diagnostics. Managed recompute and explicit open fill scope diagnostics; sync consumes a recorded external native recompute once for read-only selector/scope reconciliation. Native observer callbacks only mark boundaries, and idle status performs no exact scope boolean or selector evaluation.

Stored managed Part Studios already using `UseHasher=false` open without native recomputation. A true-hasher managed attachment switches mode and recomputes once. Native Assembly reopen retains its existing solve/recompute path, and recovery retains its reconstruction path. Engine stamps and native saved ProgramVersion produce `engine_changed`, `saved_by_other_build` or `engine_unrecorded`; absent expected stored shapes produce `missing_shapes`. Stored failed/Touched flags remain failed/unrecomputed. Retained geometry remains available for inspection, while export requires explicit Rebuild. Rebuild stamps the current engine in the same native undo step; Undo restores the old reason/stamp. Input archives are not rewritten on open.

Entity coordinates are sketch-local millimeters. Supported dimensional constraints are Distance, DistanceX, DistanceY, Diameter, Radius and Angle; angles use radians. Unnamed dimensions use keys such as `Constraints[17]`. Numeric values must be finite and satisfy native dimensional/solver validation. Source-created features may carry optional request fields `source_feature_id`/`source_feature_name`, stored in native source properties and metadata mapping.

The GUI starts a lease before native `setEdit`. Stop active drawing tools, call native `resetEdit`, then finish or cancel through the controller. During the lease, only that sketch's geometry/parameter/reference/support changes, inspect, managed undo/redo and finish are permitted. Refresh inspect after native edits. Native construction tools may commit intermediate transactions; finish groups lease transactions and cancel restores the initial sketch without deleting prior history or allowing canceled geometry to return through redo. Closed-document leases cannot survive same-UUID reopen. See [native sketch plane and lifecycle details](SKETCH_PLANE_CONTRACT.md).

Managed legacy documents retain `KurtShapeFeatureOrder` as native chronological links without enabling multi-part behavior. Native Undo may recreate deleted features in a different allocation order; the feature history and rollback sequence continue to use the accepted chronological links. `Controller.delete_features_plan(doc, features, body=None)` is a read-only GUI helper returning ordered `selected`, unselected `dependents` and total `removed` IDs, with the same target/dependency validation as deletion.

Standalone modeling failures abort their transaction and retain accepted geometry/revision. A failed managed command restores its pre-command draft; failed Finish retains the full current draft/lease and advances the revision. The GUI reopens Sketcher and shows the error in Messages. Only explicit Cancel discards the lease. Native failed builds report explicit errors; unrecomputed touched features report `needs_rebuild`, `measurements:null` and separate `retained_geometry_measurements`. Export rejects failed or unrecomputed builds. Retained geometry is not a successful evaluation of new intent.

This section supersedes the earlier multi-body, rollback and preview limitations. Existing single-Body files and requests retain their native behavior. An explicit studio operation, part appearance change or rollback lazily adopts the native feature history; no separate migration file is required. Managed files use `UseHasher=false` so the pinned runtime exposes complete composite element names. Switching that cache mode during attachment completes a native recompute before inspection.

Extrude (`pad`), Remove (`pocket`), `revolve`, `sweep`, `loft` and whole-part patterns accept `operation:"new"|"add"|"remove"|"intersect"` and `merge_scope:"auto"|[part_id,...]`. New makes independent parts. Auto chooses parts intersecting the tool, including contact for Add. An explicit scope limits target parts; it does not clip the tool. Add fuses its connected scoped targets and retains the first target's logical identity. Remove/Intersect preserve each surviving target identity. Disconnected or empty one-part outcomes reject rather than discard solids. Patterns act on generated copies; count includes the retained source. With `include_source:true` the sources act too, and they are consumed (see [Pattern tools](#pattern-tools)). Extrude supports blind, through-all and native up-to-face ends; selectors may supply `up_to_face`. A sketch-profile Extrude runs along its sketch's own +Z (Reverse flips it) whatever the profile's winding: the native `Part::Extrusion` uses `DirMode` Edge with a hidden unit `Part::Line` whose Placement expression follows the world profile binder, because native Normal mode fits an unsigned plane to a binder's edges. Extrudes created before 2026-10-17 keep their stored Normal mode. Studio booleans (Add/Remove/Intersect results, part patterns, `boolean_parts`, move face) set the native `PartDesign::Boolean.FuzzyTolerance` to 0 and keep FreeCAD's automatic fuzz (-1) only when the exact operation fails; the automatic value scales with the combined bounds, which through-all tools inflate, and left ~3e-4 mm edge tolerances on near-tangent sections that later fillets could not survive. Legacy Pad/Pocket requests omitting studio fields retain their original native path.

Managed rebuilds reevaluate automatic scopes for Extrude, Revolve, Sweep and Loft and update native target/output dependencies in the same transaction. A scope change that would require migrating an unsupported downstream native consumer fails closed. Changed automatic pattern target sets also fail closed and require reapplying the operation. Native edits outside a controller transaction can expose such changes but cannot rewrite authored dependencies; use managed Rebuild. Scope invalidation is cheap and never evaluates geometry on idle ticks.

Through-all `pad` requests require an explicit `operation` or `merge_scope` to enter the studio path. Omitting both rejects rather than silently using a finite legacy Pad. The unified GUI emits the result operation automatically.

Inspect adds `studio:{enabled,feature_order,rollback_index,parts}`; each part has stable `id`, current native `body`/`feature`, name, visibility and color. Features expose `rolled_back`, `selectors` and `reference_health`. Export includes each current part once, with `included_part_ids` alongside native Body IDs. Assembly source selection uses the same current-result enumeration.

### Pattern tools

By default a pattern with `operation:"add"|"remove"|"intersect"` applies only its generated copies. The source parts stay separate, and with an automatic scope a source can itself be a target. `include_source:true` gives Onshape feature-pattern semantics: the source parts act as tools together with their copies, and the operation consumes them, as `boolean_parts` consumes its tools. A cutter part patterned ×3 with Remove therefore cuts three holes, and only the target remains. The whole operation is one native transaction and one undo step.

- **Targets.** Source parts are never targets. An automatic scope picks from the other current parts. An explicit `merge_scope` that names a source part, by part ID or by Body name, rejects with `invalid_argument`.
- **Rejections.** `include_source:true` with `operation:"new"` (also the default operation) or `"intersect"` rejects with `invalid_argument`; `false` is accepted. Intersect against several patterned tools is ambiguous (each instance in turn, or their union) and the native multi-tool Common splits its result, so fuse the tools with `boolean_parts` first. A non-boolean value rejects with `invalid_argument`. An automatic scope with no part other than the sources rejects with `empty_merge_scope`. So does an Add whose included source or generated copy touches no target, since Add would discard that solid (`parts` lists those sources, `copies` those copies).
- **Native representation.** The history-bound source snapshots join the copies as `PartDesign::Boolean` tools. The representative records them in `KurtShapePatternToolParts` and records the source part IDs in `KurtShapePatternSourceParts`. `KurtShapeConsumedParts` holds the targets plus the sources. Rollback before the pattern, `delete_features` of it, and undo all restore the source parts. Changing a source's parameters updates every hole. Automatic-scope diagnostics leave the sources out of the target set.
- **Copy ownership.** Since 2026-10-17, pattern copies consumed by Add/Remove/Intersect carry `KurtShapeOperationOwner`, so `delete_features` removes them with their pattern. Before that, a delete of such a pattern failed with `external_dependency`. Copies in older files are found through `KurtShapePatternToolParts`.

### Datum planes

`create_plane` coordinates are world millimetres. They are converted once into the owning Body's frame at creation (the same values when the Body is at identity, which is the normal case). The plane then belongs to the Body and moves with it. Directions need not be unit length; they are normalized. A sketch on the plane (`create_sketch support:{feature:<plane id>}`, no subelement) uses the plane's frame exactly: local +X is the plane's x direction, +Y is normal × x, +Z is the normal, and the origin is the plane origin plus `offset` along the normal. A circle at sketch (10, 5) therefore lies at origin + 10·x + 5·y.

- **Point-normal.** `origin` and `normal` are required. `x_direction` is projected into the plane and rejects when parallel to the normal. When it is omitted, x is world +X projected into the plane, or world +Y when the normal is parallel to X (projection shorter than 1e-6).
- **Three-point.** The origin is the first point, x points toward the second, and the normal is (p2−p1)×(p3−p1), so the third point is on the +Y side. Points closer than 1e-7 mm or collinear points (sine below 1e-7) reject.
- **Line-angle.** The plane contains the line. Its origin is `axis.origin` and x is `axis.direction`. At `angle` 0 the normal is `reference_normal` projected perpendicular to the line, which rejects when parallel to it. A signed `angle` (radians, or a quantity such as `"108 deg"`) turns the plane right-handedly about the line direction. An edge reference or selector supplies the line's origin and direction, from its first-parameter point to its last-parameter point. The edge is copied once at creation and is not tracked afterwards. `PlaneAxisReference` records which edge was used.

Native representation: the offset mode is unchanged. It uses FlatFace on the selected support, and the native expression `AttachmentOffset.Base.z = Offset` drives it. The point-normal, three-point and line-angle modes attach FlatFace to the Body origin XY plane. A native expression drives the whole `AttachmentOffset` from Body-coordinate properties in the "KurtShape plane" group:

- `PlaneMode` (read-only)
- point-normal: `PlaneOrigin`, `PlaneNormal`, `PlaneXDirection`
- three-point: `PlanePoint1`..`PlanePoint3`
- line-angle: `PlaneAxisOrigin`, `PlaneAxisDirection`, `PlaneReferenceNormal`, `Angle`
- every mode: `Offset`

Editing these properties natively moves the plane and the sketches attached to it. Plain FreeCAD rebuilds the saved file without KurtShape. The native attachment editor shows these offsets as expression-bound.

`Offset` is a signed `set_parameter`/`set_expression` parameter for every KurtShape plane. Line-angle planes also report a signed `Angle` parameter in radians, marked `signed:true`.

Inspect adds `plane` to every datum-plane feature, with these fields:

- `mode`: `offset`, `point_normal`, `three_points`, `line_angle`, or `native` for helper planes
- `frame:{origin_mm,x_direction,y_direction,normal}`: in world coordinates; exactly the frame of an attached sketch
- `placement:{position_mm,rotation_xyzw}`: in Body coordinates
- `support` and `map_mode`
- `definition`: the authored request fields in Body coordinates (`origin`/`normal`/`x_direction`, `points`, or `axis`/`reference_normal`/`angle`/`axis_reference`), plus `offset`

Validation rules:

- Fields from two definitions in one request return `invalid_argument` with `modes`.
- Missing required fields, non-finite or boolean numbers, vectors without exactly three components, zero directions and wrong-dimension quantities return `invalid_argument`.
- An edge that is not straight returns `unsupported_axis`, and unknown fields return `unknown_argument`.
- A rejected request leaves objects, Undo and revision unchanged.
- After recompute, the native frame is checked against the request, and a mismatch returns `attachment_failed`.

The GUI Plane tool still authors the offset mode. `preview` accepts every mode, including signed line-angle angles.

### Geometry references and selectors

A geometry reference accepts `{feature,subelement:"FaceN"|"EdgeN"|"VertexN"}` or an authored selector (bare, or `{selector:...}`). Native names remain supported explicit references, not inferred persistent identities. Interactive Use sends the exact picked native edge; Sketcher retains its mapped source association. A native external geometry `Missing` flag produces a `missing_reference` build error and a missing entry in the sketch's `reference_health`, even if Sketcher retains cached geometry and reports its own state as valid. Authored selectors keep their separate query semantics. Selector syntax:

```json
{"kind":"created_by","feature":"Extrude","entity_type":"face","cap":"end"}
{"kind":"owned_by","part":"Body","entity_type":"edge"}
{"kind":"geometry","geometry":"plane","query":{"kind":"owned_by","part":"Body"}}
{"kind":"intersection","queries":[{"kind":"created_by","feature":"Extrude","cap":"end"},{"kind":"owned_by","part":"Body"}]}
{"kind":"closest","point":[10,5,8],"query":{"kind":"geometry","geometry":"plane"}}
{"kind":"geometry","geometry":"circle","radius":17.05,"query":{"kind":"owned_by","part":"Body","entity_type":"edge"}}
{"kind":"geometry","geometry":"torus","major_radius":22,"minor_radius":3,"tolerance":1e-4,"query":{"kind":"owned_by","part":"Body"}}
```

`entity_type` is face/edge/vertex; created-by cap is start/end/side. Set operations are `union`/`intersection` with `queries`, or `subtraction` with `query` and `subtract`. `adjacent` takes `query`, target `entity_type` and edge/vertex `adjacency`; `tangent` expands an edge query. `parallel` takes `query`, `direction` and optional `allow_antiparallel`; `closest` preserves all ties. Geometry filters include plane, cylinder, cone, sphere, torus, line, circle, ellipse, spline and point. Degenerated native edges (sphere poles, cone apexes) report geometry `degenerate` and match no filter. Unknown schema/history rejects. No nth-element selector exists.

A geometry filter can also match native primitive parameters in millimeters: `radius` (positive) for circle, cylinder, sphere and cone, where a cone's radius is the native reference radius at its `axis_point_mm` (it depends on how the cone was built; a cone whose reference circle sits at its apex reports 0 and cannot be radius-filtered); `major_radius`/`minor_radius` for torus and ellipse. All given parameters must match within the absolute `tolerance` (non-negative mm, default `1e-6`). A parameter on a geometry without it (such as `radius` on plane, line or torus), a non-number, zero, negative or non-finite value, or `tolerance` without a parameter rejects with `invalid_selector`; unknown keys reject as for every selector. Stored consumer selectors (fillet/chamfer edges, supports, up-to faces) keep these fields in `QueryInputs` and re-evaluate them at their regeneration position, so a fillet bound to "the radius-5 top circle" follows parameter edits that move or renumber it, and a typed edit that leaves no such circle rejects with `build_failed` instead of substituting another edge. Radii are read through the selector's cached native scalars.

`resolve_selector` returns each match's `summary`: `geometry`, `center_mm` (centre of mass), `area_mm2` (faces) or `length_mm` (edges), `normal` (planes), plus usable geometry for picking without outside math:

| Element | Added summary fields |
|---|---|
| every edge | `point_mm`: the point at the edge's mid-parameter, on the edge |
| line edge | `direction`: unit vector from the first-parameter to the last-parameter point |
| circle/arc edge | `radius_mm`, `geometric_center_mm`, `axis` (unit native curve normal) |
| ellipse edge | `major_radius_mm`, `minor_radius_mm`, `geometric_center_mm`, `axis` |
| every face | `point_mm`: a point on the face clear of its boundary: the parametric centre when it lies inside the face, otherwise the nearest inside point of a parameter grid, the projected centre of mass, or a point stepped inward from an edge midpoint (last resort: the longest edge's midpoint) |
| cylinder face | `radius_mm`, `axis`, `axis_point_mm` (native axis location) |
| cone face | `radius_mm` (reference radius at `axis_point_mm`), `axis`, `axis_point_mm`, `apex_mm`, `semi_angle_rad` |
| sphere face | `radius_mm`, `geometric_center_mm` |
| torus face | `major_radius_mm`, `minor_radius_mm`, `geometric_center_mm`, `axis` |

`center_mm` keeps its centre-of-mass meaning (for an arc it lies off the edge); use `point_mm` as a `closest` pick point. A `closest` selector at a reported `point_mm` with the same query returns that element alone for non-degenerate edges and for faces whose point lies clear of the boundary (not the last-resort edge midpoint). Faces OCCT keeps as surfaces of revolution report geometry `surfaceofrevolution` and have no parameter filter. `ambiguous_reference` errors list their `matches` with the same detailed summaries. These detailed fields are computed only for that read output and ambiguity diagnostics, never while consumers rebind during a rebuild.

Consumers store `QueryInputs` on their native feature and evaluate at that feature's regeneration position, after dependencies and before consumer recompute. Native resolved links are caches. Rebinding, input health and a bounded `QueryResolutionLog` occur inside the mutation transaction. Health is healthy/missing/ambiguous; unknown history is missing with its error code. A missing or ambiguous reference retains the last native link and never substitutes another element. Such intent has no current measurements and blocks export. A rejected typed edit rolls back; unresolved intent introduced through native editing remains visible until repaired. Evaluation compares the actual native property with the selector result, so manually changed native links cannot remain healthy merely because their JSON cache still matches. Ordinary inspection detects cheap native-link divergence; after external native recompute, sync reconciles exact derived health outside the observer callback without a nested rebuild or authored-link write. Changed resolution requires managed Rebuild, which restores the authored query. Idle inspection reads cached health without query evaluation.

Created-by traces the pinned FreeCAD 1.1.4 raw element-name branches and explicit native whole-part generator metadata, distinguishing generated/modified topology and retaining all tested refined merge ancestors. Unsupported hashed, stale or unknown maps fail closed. Caps use native extrusion/revolution/loft/sweep geometry; this is local OCCT lineage, not an Onshape topology-ID translation. GUI geometry picks author ownership, geometry and closest-point predicates explicitly; a tie becomes ambiguous. Native link/constraint parameters remain authoritative. Diagnostics records selector evaluation separately from total rebuild.
