# Assembly acceptance recipe

Run these commands from the app repository with its bundled FreeCAD Python:

```powershell
.\run-checks.ps1
.\validate-review-gui.ps1 -Scenario assembly
# After the independent hidden GUI process finishes:
& runtime/freecad-1.1.4/FreeCAD_1.1.4-Windows-x86_64-py311/bin/python.exe -B tools/validate_assembly_reopen.py
```

The GUI launcher preserves every existing scenario. `assembly` uses a separate hidden FreeCAD process and an isolated profile under `runtime/review-assembly-validation`; it never drives or closes Kurt's open modeling window. It records `validation/assembly-workflow/gui-test-result.json`, screenshots at 1200×800 and 1600×1000, and disposable saved/native/source/export fixtures in `assembly-gui-projects-working`. The final command starts a genuinely fresh native Python process, reopening the relocated GUI-produced file with the original source path absent. Its report is `fresh-process-reopen-result.json`.

`tests/test_assembly.py`, included in the offline suite, contains 15 native tests. Its asymmetric box fixture creates repeated `App::Link` occurrences, one native grounded joint and fixed/revolute/slider joints. Tests measure native connector transforms and allowed motion, command-level placement undo/redo, joint editing/renaming/cascade removal, stale tokens/request replay, incompatible native constraints, injected solver failures and rollback, busy/sketch-edit guards, and source script/nested-link rejection. Direct native placement changes invalidate current geometry and block export until a successful solve. Embedded geometry tampering blocks solve/export until native undo restores the accepted snapshot; adding a Python property to a marked embedded source cannot make it trusted or adoptable. Twenty-five idle inspections must perform no solves, source reads, BRep serialization, intent hashes or measurement recalculation.

The original `Dodec pipe mount.step` and `Dodec Hub Conformal.step` files are referenced in place. The test follows Open STEP → Save FCStd → choose each of three native Bodies → insert, then repeats one pipe Body at a translated placement. Each occurrence retains its source Body's volume and bounds; the final export has seven solids. Both originals' SHA256 values must remain unchanged. Volume comparisons sum each native Body/occurrence independently: OCCT's adaptive integration of a compound containing separated complex surfaces can differ from the sum of the same solids. This avoids treating compound-integration variance as lost geometry while retaining tight per-part comparisons.

The GUI recipe uses the actual workspace chooser, toolbar actions, Create name dialog, Insert file and Body chooser dialogs, native-reference joint dialogs, movement/rename/edit dialogs, native history, Escape cancellation and Ctrl+S. It also exercises actual Y/Shift+Y keys on native occurrences, ensuring hidden embedded snapshots stay hidden. Authenticated local HTTP requests run on a worker while the native GUI thread handles mutations: creating an assembly in an already seen Part Studio automatically updates the toolbar/history, and rejected conflicting intent produces exactly one visible message even after an identical replay. Accepted geometry, revision and undo history remain unchanged. The recipe verifies native save/reopen/relocation, occurrence export and return to the original unchanged Part Studio. Rendered screenshots must also be inspected; the JSON report alone is insufficient visual evidence.

Final targeted evidence on October 2, 2026: the 15 native assembly tests passed; the added checkpoint/recover and joint-edit rollback assertions also passed in a targeted three-test rerun. The final hidden Assembly GUI passed **58 checks**, and the separate native process passed **4 fresh reopen checks** against that exact relocated fixture (`gui-solved-assembly-40576.FCStd`). Both the settled 1600×1000 view and the reopened view were visually inspected: the four occurrences, grounding, three joint families, compact Assembly controls and visible bridge conflict message render legibly. The existing hidden STEP GUI recipe passed its **19 checks** after the Assembly changes. Reports record native engine versions and local timings; these fixture timings do not establish a large-model latency budget.

Two native integration defects were found during validation: joints had to be recomputed before invoking the native solver, and solver return zero alone did not prove that every requested connector relation was satisfied. The adapter now invokes the native solver after recompute and checks actual connector residuals and grounded placement before accepting a result. It also closes its own native global transaction after abort so diagnostic metadata cannot reopen a rejected command as an extra undo entry. The isolated fixture proves those failure paths preserve accepted references, placements, revision and native undo/redo counts.

The genuinely fresh-process gate also caught a persistence defect that same-process reopen concealed: native BRep serialization contains display meshes and a transient `Checked` topology flag. Embedded geometry fingerprints serialize a native `Shape.copy(True, False)` with geometry copied and mesh excluded, and normalize only the `Checked` bit in native topology flag records. Geometry, tolerances, transforms, topology and all other flags remain represented. This retains the immutable snapshot check while permitting genuine save/reopen across graphical and headless processes. The local harness records exact native BRep payloads in its ignored working folder to make this distinction reproducible.

Known runtime startup thumbnail/status-bar/view-provider warnings and deliberate solver-conflict messages are retained in the GUI report/log. The earlier STEP handoff's recovered `GUIApplication::notify` startup access-violation warning remains documented in `../STEP_IMPORT.md`; a passing workflow is not a claim of warning-free native startup. This is automated workflow acceptance, not Kurt's hands-on usability judgment or evidence of recovered historical STEP mates/parametric conversion.
